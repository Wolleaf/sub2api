# 上游周配额（定制版）

该模式用于安全的单一非影子 OpenAI OAuth 账号分组。每把 Key 配置
`upstream_weekly_limit_percent`（0 表示关闭），数据库约束范围为 0—100。
启用后以百分比分摊值检查周限额，原 `rate_limit_7d` 保留且继续记美元用量，
但不再作为周拦截条件。总额度、5h/1d、状态和其他限制保持生效。

## 分摊方法与边界

- 每分钟读取上游 `/wham/usage`，只接受唯一的 604800 秒窗口。
- 仅把新增加的百分比按未分摊期间各 Key 的 `usage_logs.total_cost` 增量分配；
  不用“总美元 / 百分比”外推账户容量。使用分组折扣前的记录费用，避免免费
  Fast 或客户折扣直接变成零权重。此权重仍受模型、上下文价表影响。
- 已分摊的份额在同一周内不回退。上游百分比暂时下降不会退款；只有确认
  进入新周时重置。5 分钟内的窗口时间漂移沿用原窗口。
- 初次启用将本周已观察到的上游用量按本周日志权重分摊。美元历史不重写。
- 没有可归属日志，或费用来自没有启用配额的 Key 时，相关比例记入账号
  `unattributed_percent`。并发外部用量与本地用量无法从上游汇总值精确拆开。
- **这是估算分摊，不是上游按本地 Key 返回的精确账单。**整数百分比、轮询
  延迟、跨请求计量和外部客户端可能造成偏差。达到阈值前已开始的请求可以
  在之后完成；最多存在轮询期间与已在途请求的超用。
- 初始化未完成、观测超过 10 分钟、拓扑不安全后观测过期等情况返回 503，
  不把缺失的观测当作零用量。达到份额返回 429。
- 一键开蹬临时豁免两种周限额，但不改变原配置或已使用的份额。新周、到期
  和不安全拓扑继续自动关闭豁免。

本次生产策略：三把现有 Key 各 25%，剩余 25% 作为余量；不因为 Key 数量
变化自动重分配。新增 Key 需要明确配置其配额。旧的 800 美元不是上游 25%
的等价金额。只有已认证的所有者能读取自己的 Key 份额；只读管理员仍无权
访问 Key、凭据、用户和账单。

## 展示与接口

用户 Key 列表、编辑详情和 Key 自助用量页显示“估算已用 / 分配比例”和
上游重置时间。`GET /v1/usage` 的 `upstream_weekly_quota` 包含 `limit`、
`used`、`remaining`、`unit=percent`、`estimated=true`、`observed_at` 和
`reset_at`。美元统计仍用于查看计价账单。手动美元重置不能重置上游份额。

## Sol 价格校正

`deploy/pricing-overrides.json` 基于 2026-09-07 核对的官方 Sol 促销价格：
Standard 输入/缓存输入/输出为每百万 token 4/0.4/20 美元；长上下文继续
输入侧 2 倍、输出侧 1.5 倍。OAuth Fast 继续为同来源 Standard 的 2.5 倍，
API Priority 保持自己的 2 倍规则。Astra OAuth Fast 也按官方 2.5 倍处理。

生产将覆盖文件安装到持久化 data 目录，配置 `PRICING_OVERRIDE_FILE`；
沿用上游 v0.2.1 的覆盖文件热加载，避免未更新的远端价格源恢复旧价。
官方促销至少持续到 2026-11-21，需要在届时核查官方是否续期或改价。
此文件不会自动抓取网页或自动决定促销截止后的未知价格。

## 手动美元重置修复

`rate_limit_reset_at` 单独保存手动重置基线，周窗口校准时只加减该基线之后
的历史。解决手动重置后首个请求将窗口设为零点、下一次周同步又扣除旧历史
的问题。迁移仅增加字段与观测表，不修改历史账单。
